# Changelog

Все значимые изменения проекта документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), проект следует [семантическому версионированию](https://semver.org/lang/ru/).

## [1.2.5] - 2026-10-29

### Added

- **Подробный текст ошибки при сбое 1С.** Прокси читает тело не-2xx ответа 1С и включает причину в сообщение: для страницы ошибки IIS — `HTTP 500: IsapiModule / 1C Web-service Extension / 0x80004005` (модуль / обработчик / код ошибки), для JSON — `error.message`, для текста — его начало. Раньше пользователь видел только `HTTP 500`.
- **Подсказки, что проверить.** К ошибке добавляется вероятная причина: для 500 от `IsapiModule` — «вероятно, информационную базу 1С необходимо опубликовать на веб-сервере» (и проверить сервер 1С и версию `wsisapi.dll`); для 404 — `MCP_ONEC_URL`, `MCP_ONEC_SERVICE_ROOT` и HTTP-сервис MCP; для 502/503/504 — веб-сервер или прокси перед 1С; для прочих 5xx — журнал регистрации 1С.
- **Типизированные сетевые ошибки.** Отказ в соединении, DNS-ошибка и таймаут приходят как `Нет связи с 1С (ECONNREFUSED)` с подсказкой, а не как «fetch failed».
- Сводка и подсказка выводятся в ответе MCP на `initialize` (`1C service unavailable: …`), на странице входа OAuth2, в `/token` и в ответах инструментов, ресурсов и промптов.
- Документация для сопровождающих: `.docs/deploy-production.md` — подключение к production-ВМ, обновление, откат и диагностика ошибок 1С. Переменные `MCP_DEPLOY_SERVER`, `MCP_DEPLOY_USERNAME`, `MCP_DEPLOY_PASSWORD`, `MCP_DEPLOY_DIR` описаны в `.env.example` (прокси их не читает).
- `AGENTS.md` — единые инструкции для AI-агентов; `CLAUDE.md` ссылается на него.

### Changed

- Ошибки инструментов, ресурсов и промптов при сбое 1С больше не содержат стек вызовов с внутренними путями контейнера — только сводку и подсказку.
- Полные подробности ответа 1С (URL и физический путь на веб-сервере) пишутся только в лог (`1С ответила HTTP …`, `Нет связи с 1С […]`) и не попадают клиенту и на страницу входа.

### Fixed

- Отказ авторизации (401/403) определяется по коду ответа, а не по тексту сообщения: сбой с кодом 502 и текстом «HTTP 401» в теле больше не принимается за неверный пароль и не засчитывается в лимит попыток входа.

## [1.2.4] - 2026-08-30

### Fixed

- **Устранена внезапная потеря авторизации MCP-клиентов («requires re-authorization (token expired)»).** Две причины:
  - Использованный (ротированный другой сессией) refresh-токен вычищался через 1–2 минуты, и опоздавшая параллельная сессия получала `invalid_grant` («Недействительный или истекший refresh token» в логах), а в узком окне до очистки — отзыв ВСЕЙ цепочки токенов (строгая трактовка RFC 6819 §5.2.2.3) с разлогином всех сессий разом. Для MCP-клиентов это штатная ситуация: несколько окон Claude Code делят один файл креденшилов и при истечении access-токена обновляют одну и ту же пару вразнобой. Теперь по умолчанию (лояльный режим) использованные refresh-токены хранятся, пока жив выданный при ротации access-токен, и повторное использование идемпотентно возвращает актуальную пару, догоняя опоздавшую сессию по всей цепочке ротаций. Строгий режим доступен через `MCP_OAUTH2_REVOKE_ON_REUSE=true`. Grace-window увеличен с 60 сек до 5 мин (`MCP_OAUTH2_REFRESH_GRACE_MS=300000`).
  - Финальный снапшот токенов при остановке сервера мог вернуть уже идущую запись с устаревшим состоянием — токены, ротированные за секунды до SIGTERM, терялись, и после рестарта клиент получал `invalid_grant`. Теперь `saveSnapshot` дожидается идущей записи и записывает актуальное состояние.

### Added

- Проба записи OAuth2-снапшота при старте: если каталог недоступен (типично — bind-mount `./data`, созданный root'ом, при процессе под `node`), в лог пишется явная `ERROR`-строка с подсказкой (`chown -R 1000:1000`), а не тихий warning раз в 30 сек.
- В Docker-образе персистентность токенов включена по умолчанию (`ENV MCP_OAUTH2_STORE_PATH=/app/data/oauth2.json`), каталог `/app/data` создаётся с владельцем `node`; `docker-compose.yml` переведён на именованный том — запись снапшота работает из коробки без ручного `chown`.
- Переменная `MCP_OAUTH2_REVOKE_ON_REUSE` — строгий режим отзыва семьи токенов при позднем повторном refresh (по умолчанию выключен).

## [1.2.3] - 2026-08-29

### Security

- **`save_file`: запрет записи в произвольный путь.** В HTTP-режиме файлы пишутся только в белый каталог (`MCP_SAVE_FILE_DIR`, по умолчанию служебный каталог во временной директории); `path` за его пределами отвергается. Имя файла из `Content-Disposition` санитизируется (только базовое имя) — закрыт path traversal со стороны ответа 1С. В stdio-режиме без `MCP_SAVE_FILE_DIR` поведение прежнее (доверенный локальный запуск).
- **Лимит тела запроса 50 МБ оставлен только для `/mcp`.** Остальные эндпоинты (включая неавторизованные `/token`, `/authorize`, `/register`) принимают максимум 100 КБ — закрыт вектор исчерпания памяти большими телами; превышение отвечает `413`.
- **Кап одновременных сессий `/mcp`** (`MCP_MAX_SESSIONS`, по умолчанию 1000): при превышении вытесняется самая старая неактивная сессия — initialize-шторм больше не исчерпывает память; сессии с открытыми SSE-стримами не вытесняются.
- Health-check при создании сессии идёт через кэширующий валидатор (TTL 10 сек) — массовая переинициализация клиентов после рестарта прокси не создаёт шторм запросов к 1С.
- **Защита от DNS rebinding** (`MCP_ALLOWED_HOSTS`): опциональный белый список `Host`-заголовков; запрос с чужим Host получает `403`. Рекомендуется для локальных запусков с `MCP_AUTH_MODE=none`.
- **CORS**: чужому origin больше не отдаётся `Access-Control-Allow-Origin` с первым разрешённым значением — заголовки выставляются только для origin из белого списка (плюс `Vary: Origin`).

### Fixed

- **Прозрачное восстановление сессий `/mcp`** — устранена периодическая ошибка `Invalid session` у клиентов (Claude Code и др.) после простоя или рестарта сервера. Причина: сессия жила 30 минут без запросов, при этом открытый SSE-стрим активностью не считался (после обновления SDK до 1.30.0 с keep-alive стрим перестал переоткрываться и «случайно» продлевать сессию), а на неизвестную сессию сервер отвечал `400` вместо требуемого спецификацией MCP `404` — клиент показывал ошибку вместо переинициализации.
- На неизвестную/истёкшую сессию `/mcp` (POST/GET/DELETE) сервер теперь отвечает `404` с JSON-RPC кодом `-32001` (`Session not found`) — спецификация MCP обязывает клиента прозрачно создать новую сессию.
- Открытый SSE-стрим (GET `/mcp`) и незавершённые запросы удерживают сессию от вычистки по TTL; отсчёт TTL начинается после закрытия последнего соединения.
- `InitializeRequest` с устаревшим `Mcp-Session-Id` создаёт новую сессию вместо ошибки (лояльное восстановление для клиентов, не сбрасывающих заголовок).
- Graceful shutdown принудительно закрывает keep-alive и SSE-соединения (`closeAllConnections`) — остановка больше не зависает в ожидании долгоживущих стримов; ошибки middleware (например, `413 Payload Too Large`) больше не подменяются на `500`.

### Added

- Переменная `MCP_SESSION_TTL_MS` — TTL HTTP-сессии `/mcp` без активности; по умолчанию увеличен с 30 минут до 24 часов.
- Интеграционные тесты жизненного цикла сессий `tests/http-session.test.ts` (мок 1С + реальный HTTP-сервер): коды ответов по спецификации, переинициализация, выживание сессии с открытым SSE-стримом, вычистка по TTL.
- **Request-логирование**: каждый HTTP-запрос пишется в лог с методом, путём, статусом, длительностью, IP и session id — успешные на уровне `DEBUG`, ответы с ошибками (4xx/5xx) на `WARNING`. Инциденты вида `404 Session not found` теперь видны в логах без включения DEBUG.

### Changed

- Из `runHttpServer` выделена функция `createHttpApp` (express-приложение + освобождение ресурсов) — для тестируемости HTTP-слоя.

## [1.2.2] - 2026-08-27

### Added

- **Защита от перебора паролей** (`AuthRateLimiter`): эндпоинты `/authorize` и `/token` (password grant) считают неудачные попытки входа по IP и по логину; после лимита (по умолчанию 5 попыток за 15 минут) — блокировка с экспоненциальным backoff (от 1 минуты до 1 часа) и ответ `429 Too Many Requests` с заголовком `Retry-After`. Настройки: `MCP_AUTH_RATE_LIMIT_MAX_ATTEMPTS` (0 — отключить), `MCP_AUTH_RATE_LIMIT_WINDOW_MS`, `MCP_AUTH_RATE_LIMIT_BLOCK_MS`.
- Переменная `MCP_TRUST_PROXY` (express `trust proxy`) — корректное определение IP клиента за reverse proxy; без неё блокировка по IP видела бы только адрес прокси.
- Переменная `MCP_AUTH_RATE_LIMIT_BY_IP` (по умолчанию `true`) — отключение учёта IP при подсчёте неудачных попыток для окружений, где все клиенты видны с одного адреса (Docker Desktop, прокси без `X-Forwarded-For`); блокировка по логину при этом сохраняется.
- Тесты: `tests/rate-limit.test.ts` (лимиты, эскалация блокировки, окно, сброс при успехе, cap памяти) и новые кейсы `config` для параметров rate limiting и `trustProxy`.
- Защита памяти лимитера: ключи длиннее 128 символов (например, гигантский «логин» в теле запроса) заменяются на SHA-256-хеш, память ограничена жёстким капом в 10 000 записей (~единицы МБ в худшем случае).
